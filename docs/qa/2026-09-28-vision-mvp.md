## Owner statement (verbatim, 2026-09-25)
"I want to modify the vision: the project IS NOT about just 60 minute BTCUSD, it shouldn't be constrained
to a timeframe or a ticker. The grand vision is neural network that is a financial complex time series
predictor based on gradient technical indicator parameter and combination. It is a substitute for manual
technical indicator search and analysis. The project therefore just chose that particular timeframe and
ticker for most effectiveness, noise and complexity. The ticker, timeframe should be configurable in the
future. Right now the biggest growth points towards MVP are:
- Project code and file structure organization
- Visual richness and intuitive comprehension of learning, inference, backtest
- Mathematical gradient stability. unified gradient stability testing framework
- Configuration control panel: grid searches, results, leaderboards, unifying testing framework
- Testing and Comparison: different config scenarios in unified control framework"

## Round 7 (comparison rules, GPU use) - all recommended options
- Seeds: 1 SEED PER TRIAL per dev fold; top 5 re-run with 3 seeds; final order and winner by the seed mean.
- Parallel GPU: N concurrent runs ONLY while the other project leaves the GPU idle, N from one measured
  throughput test; otherwise one at a time.
- Verdict rule (A vs B): PAIRED TEST over (seed, fold) pairs on the same blocks + pre-registered MINIMUM
  EFFECT; guard-rails judged by the same test.
- Determinism: OPT-IN deterministic mode for comparison studies after a measured speed test; sweeps stay fast.

## Round 8 (gradient stability)
- Stable = INVARIANTS (CI) + PER-RUN HEALTH + ON-DEMAND HARNESS (scale/vol sweep x0.1..x10, fuzzing, NaN
  injection, 3 seeds; thresholds pre-registered; every new ticker/timeframe/horizon setup must pass).
- Diagnostics cost: <=2% of sec_per_step by default; per-term probe (~10%) behind a flag.
- Failure (owner's words): "attribute and fail loudly, but this should be configured to not allow a
  configuration of hyperparameters that would fail the system" -> per-term attribution, strict mode in CI and
  harness, failed runs marked failed (Optuna prunes); AND config validation / sweep search spaces must reject
  hyperparameter regions known (from the harness) to fail, before a run starts.
- Maths: MEASURE + ONE pre-registered A/B of gradient-based loss weighting vs today's value calibration.
