## STRAT-1: assert_no_lookahead misses one-bar peeks: exit signals and TP/SL levels are never compared, and 3 probes catch a peeking decide() only by chance

- **Severity:** P1. **Status:** confirmed. **Type:** test-gap. **CPU cost:** instant. **Placement:** new item CPU-03.
- **Files:** `src/neural_trade/strategy/backtest.py`, `tests/test_backtest.py`, `README.md`

**Description.** assert_no_lookahead (backtest.py:339-359) compares only (a) the entry decisions dict {bar, side, size, reason} (backtest.py:251-252, 352-355) and (b) equity[:t+2] (backtest.py:357). What is decided at bar t's close but only takes effect at t+1 is never compared: the exit request from exit_signal (backtest.py:244-247, not recorded anywhere) and the order's tp/sl/tp_is_offset/max_hold (not in the decisions dict). Both affect equity only from index t+2, which the check excludes. In addition, only 3 probe bars are used (backtest.py:347; the test passes probes=(120, 250, 380) at test_backtest.py:137), so a peeking decide() is caught only if the strategy happens to be flat at a probe and the perturbation flips its choice. The existing positive control (test_backtest.py:140-150) peeks 5 bars ahead, which hides this. README.md:179-180 claims the self-test 'checks that nothing up to t changes'. The ROADMAP trading exit criterion (NT-005) requires 'look-ahead checked', so a new strategy written for NT-005 can pass this guard while peeking one bar ahead.

**Failure scenario.** A strategy that reads bar t+1 in any of three places passes the look-ahead self-test. Example: an exit_signal that exits when s.close[t+1] < s.close[t], or a take-profit set at the next close (a perfect limit). Input: tests/test_backtest.py::_frame(500, seed=3) with probes (120, 250, 380), as in test_no_lookahead_all_strategies. Output: no AssertionError for 7 of 8 one-bar-peek mutants. The exit and TP-level peeks are missed even when every bar is probed.

## STRAT-2: 'Gross' return, gross Sharpe and gross percentile depend on the cost setting: the gross book is sized from net equity

- **Severity:** P2. **Status:** confirmed. **Type:** bug. **CPU cost:** instant. **Placement:** new item CPU-10.
- **Files:** `src/neural_trade/strategy/backtest.py`, `src/neural_trade/notebook/backtest_ui.py`, `scripts/backtest_gate.py`

**Description.** Each position is sized from net equity: notional = size_frac x equity_cash (backtest.py:208). equity_gross adds that position's P&L to gross_cash and uses the same net-sized unrealised P&L (backtest.py:189-191, 255-257). As costs eat into net equity, later positions shrink, and the 'gross' curve shrinks with them. So equity_gross, sharpe_gross (backtest.py:260, performance.py:49) and every 'gross return' computed as summary['gross_pnl'] / initial_equity are not a before-costs counterfactual: they fall as costs rise. Affected displays: backtest_gate.py:64, backtest_ui.py:463, 480 and 550 (labelled 'gross return (before costs)' at backtest_ui.py:95), and the matched null's percentile_gross_return (backtest_ui.py:225, 235). Decisions never depend on equity, so the true cost-free counterfactual is well defined: the same trades with zero costs. The bias is not one-signed in general, because the weights fall over time. Here it shrank the gross figure by 12-40%. It feeds the 'gross vs net' diagnostics in STATUS.md:26 (+2.3% gross) and NT-005's 'gross +4.1% (the same as buy-and-hold)'. For m6 (net -23.4%, gross_pnl $407.95), a first-order estimate of the cost-free gross is about +4.6%, above buy-and-hold's gross $436 / +4.4% (estimate, not reproduced: predictions_test.npz is not in git).

**Failure scenario.** random_signal (trade_rate 0.2, hold 3) on _frame(2000, seed=9), 257 trades, identical in every run. fee 0 bps/side: gross_pnl/init +0.9254%, sharpe_gross +13.24. fee 13: +0.5582%, +10.84. fee 30: +0.2613%, +6.84. A before-costs number should not move. For calibrated_quantile (98 trades, net -12.8%), the reported gross is +11.04% while the zero-cost run returns +12.51%.

**Evidence (finder, reproduced).** agents/strategy-backtest/repro_metrics.py (gross invariance block) and repro_engine.py R2, run on the unmodified copy. Output: 'fee  0 bps/side: n 257 gross_pnl/init +0.9254% sharpe_gross +13.243 | fee 13: +0.5582% +10.841 | fee 30: +0.2613% +6.838'. For calibrated_quantile: 'gross_pnl / initial +11.0400%, equity_gross[-1]/initial-1 +11.0400%, cost-free run total_return +12.5066%'. Prototype fix in agents/strategy-backtest/fix2 (a parallel cost-free book: qty_gross = size x gross_cash / open, equity_gross uses it, and summary gains gross_return). check_fix2.py shows gross_return and sharpe_gross identical at fee 0/13/30 and equal to the zero-cost run for random_signal (0.00925355 / 13.2434), calibrated_quantile (0.12506602 / 166.1123) and enhanced_multi_horizon (0.08093168 / 116.9382). tests/test_backtest.py: 29 passed with the prototype.

**Verifier (reproduced): confirmed.** notional = size_frac x equity_cash, and equity_cash is the net equity (backtest.py:208). gross = sign x qty x (exit - entry) with that qty (:189), and equity_gross uses the same qty (:255-257). So 'gross' shrinks as costs erode the net equity that sizes later trades. agents/verify-strategy-backtest/v2b_gross.py, random_signal(trade_rate 0.2, hold 3, seed 0) on _frame(2000, seed=9), 257 trades in every run. Consumers: backtest_ui.py:95 (row labelled 'gross return (before costs)'), :225, :227, :235 (null gross percentile), :463, :480, :550; backtest_gate.py:64.

**Verifier corrections.** STATUS.md's '+2.3% gross' line is now STATUS.md:36, not :26. Scope the impact precisely. Per-trade gross (Trade.gross_pnl / notional, used by trade_analytics and by NT-005 (b)'s 'mean gross edge per trade in bps') is NOT affected: it is the true before-cost P&L of each trade actually taken. Also unaffected: the net numbers and the ranking metric (net Sharpe). Affected: the aggregate gross return, sharpe_gross and the gross null percentile. ## STRAT-5: Stop and take-profit fill order ignores the bar's price sequence (an open already beyond a level; close mode fills the stop at the stop price)

- **Severity:** P3. **Status:** confirmed. **Type:** bug. **CPU cost:** instant. **Placement:** new item CPU-23.
- **Files:** `src/neural_trade/strategy/backtest.py`, `tests/test_backtest.py`

**Description.** (a) When stop and target are both touched in one bar, the engine applies same_bar_tiebreak blindly (backtest.py:229-231). But the open is the bar's first price: if the open is already through one level, that level fills first, at the open. With sl_first and an open that gapped above the TP, the engine books the stop instead (too pessimistic). With tp_first (offered in the notebook widget, backtest_ui.py:507) and an open that gapped below the stop, it books the TP (optimistic). (b) With tp_sl_on='close' (backtest.py:222, also in the widget), the stop triggers only when the close crosses it, yet it fills at min(sl, open) (backtest.py:234): a price better than the observed close, although in close mode the crossing is only known at the close. TP in close mode fills at the TP, below the close (pessimistic). On the committed BTC 1-minute data the open-to-previous-close gap is at most 1.2 bps (median 0), so (a) almost never happens with the default path; (b) and tp_first are user-selectable.
