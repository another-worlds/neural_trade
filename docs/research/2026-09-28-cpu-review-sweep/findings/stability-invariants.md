## STAB-1: Evidence for NT-029/NT-038: Config.validate accepts indicator periods <= 1 and MOMENTUM_CLIP_MIN < 1, which put NaN into the learned periods and freeze the run silently; periods longer than the window are clipped without notice

- **Severity:** P1. **Status:** confirmed. **Type:** bug. **CPU cost:** instant. **Placement:** addition to NT-029, NT-038.
- **Files:** `src/neural_trade/core/config.py`, `src/neural_trade/utils/math.py`, `src/neural_trade/models/layers/learnable_indicators.py`, `src/neural_trade/models/gru_attention.py`, `src/neural_trade/training/custom_model.py`

**Description.** Config.validate (core/config.py:234-293) checks only 0 < MOMENTUM_CLIP_MIN < MOMENTUM_CLIP_MAX (config.py:286-287) and nothing about MA_SPANS, MACD_SETTINGS, RSI_PERIODS, BB_PERIODS (config.py:142-145). logit_from_period (utils/math.py:47-60) uses alpha = 2/(p+1): for p < 1 alpha > 1 and log(1 - alpha) is NaN; p = 1 gives the saturated logit 18.4. The layer initialises its logits from the configured periods (learnable_indicators.py:51-101) and clip_learned_periods (learnable_indicators.py:300-314) cannot repair a NaN (clip_by_value keeps NaN). With MOMENTUM_CLIP_MIN in (0, 1) the clip's upper logit bound is itself NaN, so the first clip after step 1 writes NaN into all 18 logits. The Bi-GRU (gru_attention.py:62) mixes the NaN channel into every head; the model maps NaN price to 0 and variance to 1 (gru_attention.py:191-212) and the loss maps direction to 0.5 (losses/functions.py:522-530), so the loss stays finite while every weight gradient is NaN; the guard (custom_model.py:474-484) zeroes each update and only counts it, and nothing outside the figures reads that counter (training_dashboard.py:708, :1445; notebook/session.py:302). With D-022 wall-clock units (NT-041) and NT-046's periods in wall-clock time, sub-bar periods and windows shorter than the textbook periods become ordinary configurations (a 60-minute window of 5-minute bars is 12 bars).

**Failure scenario.** Config(MOMENTUM_CLIP_MIN=0.5) (or an Optuna space sampling it from [0.5, 5]) is accepted; after the first step all 18 learned periods are NaN, every later update is zeroed, and the run completes, is evaluated and served with its step-1 weights and would be scored on the leaderboard as a real trial. Config(MA_SPANS=[0.5, 10, 30]) does the same from step 0 (channel 0 NaN for every window). Config(RESAMPLE_MINUTES=5, LOOKBACK=12) is accepted and trains MA 30, MACD slow 26/35/17, RSI 14/21 and BB 20/25 as 12 bars without notice, and the direction skip loses 3 of its 8 features.

## STAB-4: Correction to NT-036: the finite-step guard checks each gradient element but not the norm, so a finite gradient whose global norm overflows float32 passes and clip_by_global_norm writes NaN into every weight; and a guarded step still moves every weight through Adam's momentum

- **Severity:** P2. **Status:** confirmed. **Type:** bug. **CPU cost:** instant. **Placement:** addition to NT-036, NT-054.
- **Files:** `src/neural_trade/training/custom_model.py`

**Description.** custom_model.py:474-484 sets step_finite = is_finite(total) AND every gradient element finite. tf.linalg.global_norm (:475) overflows to inf when one element exceeds ~1.8e19 or many large elements add up, while every element is finite, so step_finite stays True; tf.clip_by_global_norm (:501-507) then returns NaN for every gradient of the group (TF makes the scale NaN for a non-finite norm) and apply_gradients (:510-511) writes NaN into every weight: exactly the failure the guard's comment (:471-473) says it prevents. NT-036 (5) tests NaN injection in the input, one gradient and one loss term only, which this case bypasses. Second: on a guarded step the gradients are zeroed but both optimizers still run (:510-511) and clip_learned_periods still runs (:519); Adam's first moment keeps moving every weight and iterations advance, so 'zero the whole update' (:472-473) is not what happens.
