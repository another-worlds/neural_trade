## VIZ-1: Variance figure crashes (ZeroDivisionError) when a conformal interval covers every sample of the block

- **Severity:** P2. **Status:** confirmed. **Type:** bug. **CPU cost:** instant. **Placement:** new item CPU-33.
- **Files:** `src/neural_trade/visualization/analytics_variance.py`

**Description.** Row 3 of variance_analytics_figure adds the conformal miss ratio `miss / 0.10` to `tail_lo` without a positivity check (analytics_variance.py:512-514). The Wilson bounds next to it are filtered to v > 0 (:507-508). When a horizon's conformal coverage is 1.0, miss = 0, so `lo_r = min([0.5] + [0.85 * v ...])` becomes 0 (:581). `_log_ticks(lo_r, ...)` (:584) then computes `np.log10(hi / lo)` on Python floats (:302) and raises ZeroDivisionError, and `np.log10(lo_r)` at :586 would be -inf anyway. The whole figure is lost; notebooks 01 and 04 call it at scripts/notebooks/build.py:188 and :422. Related divisions in the row-5 titles, `c1 / c0` and `g1 / g0` at :386 and :389, raise the same error when the first half of the block has zero mean width. Empty halves when n < 2 also make these ratios meaningless.

**Failure scenario.** (a) A 3000-sample test frame whose h2 conformal intervals cover every sample (an over-wide conformal scale, e.g. fitted in a calmer regime) gives ZeroDivisionError at analytics_variance.py:302 and the notebook cell aborts. (b) Tiny blocks, such as quick-mode sweeps (NT-030) or MAX_SEQUENCE_COUNT slices: frames of 1, 2 or 7 samples crash the same way, and so does a frame whose moves all sit inside the intervals. Even with perfectly calibrated 90% intervals at h = 20 bars, a 130-sample block covers every sample in 6.7% of blocks (simulated) and a 333-sample block in 0.13%.

**Evidence (finder, reproduced).** Ran agents/visualization-correctness/probe_var_crash.py: 'coverage h2: 1.0' then '(1) CRASH ZeroDivisionError float division by zero 302'. Ran edge_harness.py: 'FAIL n=1 / n=2 / n=7 / all_in_deadband variance_analytics ZeroDivisionError: float division by zero @ [analytics_variance.py:584, analytics_variance.py:302]'; the other four analytics figures built on the same frames. Ran sim_fullcov.py (numpy random walk, interval +/-1.645 sigma sqrt(h)): 'n=130 h=20: P(... covers every sample) = 0.0673', 'n=333 h=20: 0.0013'. Code: analytics_variance.py:507-508 filter `if v > 0` for the Wilson bounds but :513-514 append miss/0.10 unconditionally.

**Verifier (reproduced): confirmed.** scratchpad/agents/verify2-visualization/v1_variance_crash.py (synthetic PredictionFrames, no model, at 330ba2f; visualization/ is unchanged since ffb1b67): (A) 3000 samples, h0/h1 calibrated, h2 intervals x5 -> coverage h2 1.0 -> ZeroDivisionError 'float division by zero' at analytics_variance.py:584 -> :302. (B) The same frame with calibrated intervals (coverage 0.908/0.908/0.906) builds; row-3 range (-0.71, 1.19). (C) Calibrated frames of n = 1, 2, 7 and 30 all crash the same way (h1/h2 coverage 1.0). (D) A 3000-sample frame whose first-half conformal widths are 0 -> ZeroDivisionError at :385 (c1 / c0). (E) Visualizations.build('variance_analytics', ...) crashes the same way. (F) numpy random walk, overlapping 20-bar targets, 90% intervals, 3000 reps: P(block covers every sample) = 0.28 (n=60), 0.078 (n=130), 0.0013 (n=333), 0 (n=1000). Why it raises instead of giving inf: cov_conf is a Python float (variance_summary :244), so lo_r = min([0.5, ..., 0.0]) = 0.0 and hi / lo at :302 is Python float division. No test covers it: tests/test_viz_variance.py and tests/test_viz_analytics_all.py build only frames with ~90% coverage. Side check (v1b_nan_iv.py): a frame with all-NaN intervals (what Predictor.predict returns with calibrated=False or no pipeline, serving/predictor.py:102-106) does not crash but prints 'coverage: conformal 0.000' and draws a 10x miss marker.

**Verifier corrections.** Lines at 330ba2f: the Wilson filter is at :507-508; the conformal miss is appended without a filter at :512-515; lo_r :581, the _log_ticks call :584, np.log10(lo_r) :586, the division :302. In row 5, c1 / c0 is at :385 (not :386), and g1 / g0 is at :386 and :389. Notebooks call the figure at build.py:188 and :422. Reach: not on today's notebook blocks (the test block is ~7,236 samples with coverage 0.90-0.91, gate M4). It is reached on small blocks (a MAX_SEQUENCE_COUNT / quick-mode run gives ~100-sample blocks: about 8-28% per 20-bar horizon), on a block with a mis-scaled conformal quantile, and on tiny cal blocks (n < 10 always covers). The row-5 zero-width case needs zero-width intervals or sigma = 0 over half a block, which is contrived, but the guard costs one line. Acceptance (1)-(4) as proposed, plus: (5) a frame with all-NaN intervals prints no conformal coverage. No backlog item covers it: NT-015 changes only row 2's PIT band, and NT-020/NT-023 are polish.
