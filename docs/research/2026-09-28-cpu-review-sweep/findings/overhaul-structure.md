## STRUCT-1: golden_run.py verify passes when numbers turn into NaN (a partly or fully NaN array counts as 'no number changed')

- **Severity:** P1. **Status:** confirmed. **Type:** bug. **CPU cost:** instant. **Placement:** new item CPU-01.
- **Files:** `scripts/golden_run.py`

**Description.** D-023 makes `scripts/golden_run.py verify` the 'no number changed' check for every module move (NT-026 (8), NT-027 (5), NT-028 (7), NT-042 (3), NT-046 (5), NT-049 (4)). The comparison at golden_run.py:95-101 zeroes the difference only where BOTH sides are NaN (`both_nan`). Where only one side is NaN, `diff` is NaN, and `np.nanmax(diff - tol)` then ignores it. If a whole array becomes NaN, nanmax returns NaN, and `NaN > 0` is False. Either way the key counts as passed, and `ok = not bad and not missing` (line 110) returns exit code 0 with {"golden_equal": true}. So a refactor that makes a loss, a metric, a learned period or a prediction non-finite passes the guard. It also passes when a NaN in the recording turns into a finite value.

**Failure scenario.** Recording: pred/delta/h1 = [1, 2, 3], hist/val_loss = [0.5, 0.4], period/ma_0 = [14]. After a module move the run returns pred/delta/h1 = [1, NaN, 3], or hist/val_loss = [NaN, NaN], or period/ma_0 = [NaN]. `golden_run.py verify` prints 'ok' for every key and exits 0. A real change of 1.0 in the same array is correctly flagged (exit 1).

**Evidence (finder, reproduced).** Reproduced without training. I copied scripts/golden_run.py to agents/overhaul-structure/golden/ and replaced `run()` with a stub that returns fixed dicts (probe_nan.py), then called `main(['verify', ref.npz])`. Output: CASE 'identical' exit 0; CASE 'one value becomes NaN' -> all 'ok', {"golden_equal": true}, exit 0; CASE 'whole array becomes NaN' -> 'ok hist/val_loss max|diff|=nan' plus a RuntimeWarning 'All-NaN slice encountered', exit 0; CASE 'period becomes NaN' -> exit 0; CASE 'value changed by 1.0' -> 'FAIL pred/delta/h1 max|diff|=1', exit 1. Code: golden_run.py:95-99 (`both_nan = np.isnan(a) & np.isnan(b)`; `diff = np.where(both_nan, 0.0, np.abs(a - b))`; `excess = float(np.nanmax(diff - tol))`), :101 (`bad = [w for w in worst if w[0] > 0]`). No test covers golden_run.py (grep 'golden' in tests/: none).

**Verifier (reproduced): confirmed.** Re-read scripts/golden_run.py:95-101,110 at ffb1b67 (code identical to 7785ec9): both_nan zeroes only NaN-on-both-sides; one-sided NaN makes diff NaN and np.nanmax(diff - tol) skips it; an all-NaN key gives nanmax=NaN and NaN > 0 is False. Ran agents/verify-overhaul-structure/golden/probe.py (loads the real script, replaces run() with fixed dicts, calls main(['verify', ref.npz]); no TF imported). Exit codes: identical 0; one element -> NaN 0 ({"golden_equal": true}); whole array -> NaN 0 (RuntimeWarning 'All-NaN slice encountered'); period -> NaN 0; recorded NaN -> finite 0; value changed by 1.0 -> 1 (FAIL). Not covered by any BACKLOG item: NT-026 (8), NT-027 (5), NT-028 (7), NT-029 (5), NT-036 (2), NT-041 (2), NT-042 (3), NT-046 (5), NT-049 (4), NT-054 (3) all use verify as a guard; none checks the script.

**Backlog check (finder).** BACKLOG NT-001..NT-052, ROADMAP, STATUS and the archived plan only use golden_run as a guard (NT-026 (8), NT-027 (5), NT-028 (7), NT-042 (3), NT-046 (5), NT-049 (4), ROADMAP MVP-4 exit). No item checks the script itself. New.
